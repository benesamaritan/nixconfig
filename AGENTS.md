# AGENTS.md — nixconfig

Personal Nix setup for a regular (non-NixOS) Linux machine. Nix is the package
manager (via Determinate Nix); user environment is managed with standalone
Home Manager through a flake. There is no NixOS host configuration on `main`.

## Layout

- `flake.nix` — inputs + the single output `homeConfigurations."benesamaritan"`.
- `users/<name>/home.nix` — per-user entry point; imports profiles, services,
  and the `nix-index-database` home-manager module.
- `profiles/` — composable Home Manager bundles:
  - `dev/` — shell aliases/paths (`config.nix`), CLI + Nix tools (`tools.nix`),
    editors (`editors.nix`), `gh`/AI CLIs (`platforms.nix`).
  - `personal/` — fonts, CLI tools, browsers (zen, helium), productivity,
    catppuccin theming.
  - `work/` — work tools; import currently commented out in `home.nix`.
- `services/` — user services (`services.user.nix`: ssh-agent, kdeconnect;
  gpg-agent present but disabled).
- `secrets.nix` + `secrets/` — agenix recipients + encrypted secrets, wired via
  `users/<name>/age.nix` (identity `~/.ssh/id_age`, token injected with
  `nix.extraOptions = "!include …"`, so `nix.checkConfig = false`). Rekey with
  `nix run github:ryantm/agenix -- -r` from the repo root after recipient
  changes. Do not delete without asking.
- `TODO.md` — task list; update it when finishing a listed item.
- `result` — `home-manager build` output symlink (git-ignored).

## Commands

Run from the repo root:

```sh
home-manager switch --flake .#benesamaritan   # apply user config (also: nh home switch)
home-manager build --flake .#benesamaritan    # build without activating
nix flake lock                                # after adding/changing flake inputs
```

## Determinate Nix rules (do not violate)

- `/etc/nix/nix.conf` is generated by Determinate — never edit it. System-wide
  tweaks (e.g. `trusted-users`) go in `/etc/nix/nix.custom.conf` (needs sudo).
- Flakes and `nix-command` are enabled by default. Keep Home Manager's `nix.*`
  minimal: never put secrets in `nix.settings` (generated `nix.conf` is a
  world-readable store file — use `nix.extraOptions = "!include …"` pointing
  at an agenix-decrypted file instead, with `nix.checkConfig = false`);
  `nix.package` is required when generating `nix.conf` but is validation-only
  (Determinate Nix stays the active `nix`); a user-level `nix.conf` cannot set
  `trusted-users`.
- Flake-level `nixConfig` substituters in `flake.nix` only take effect once
  accepted into `~/.local/share/nix/trusted-settings.json`.
- Git commits in this repo are GPG-signed (`commit.gpgSign = true` in the user
  config). Never commit unless explicitly asked; if asked to commit in an
  environment without the key, use `git -c commit.gpgSign=false` inline (do not
  change git config).

## Conventions

- Home Manager modules receive flake inputs via `extraSpecialArgs`
  (`{ ..., inputs, ... }:`), e.g. `inputs.zen-browser.homeModules.twilight`.
- `programs.nix-index` (bash integration) + `nix-index-database.comma` provide
  `command-not-found` via the prebuilt `nix-index-database` DB. Never add
  `nix-index` to `home.packages` (conflicts with the DB wrapper).
- GUI apps on non-NixOS go through nixGL (`targets.genericLinux.nixGL`).
- Catppuccin (mocha, pink) theming via the `catppuccin` flake's home module.
- Dotfiles (wezterm, helix, starship, …) live in a separate `dotfiles` repo and
  are linked with `config.lib.file.mkOutOfStoreSymlink` in `home.nix`.
- Unused flake input `affinity-nix` is kept intentionally (with its substituter).
- `legacy-nixos` branch preserves the old NixOS config (`hosts/`, `modules/`).
  Never reintroduce NixOS modules onto `main` without asking.
